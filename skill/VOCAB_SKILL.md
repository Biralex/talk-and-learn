# English Video Vocabulary

Получает транскрипт английского YouTube-видео, отбирает лексику B1+ и добавляет слова в базу повторений.

## Для кого эта лексика

Пользователь — не носитель и учит английский для живой речи. Ему нужна **простая, разговорная, часто употребляемая лексика** уровня B1–B2. Редкие, узкоспециальные, книжные значения (уровня C1 и выше, «в очень узких кругах») только мешают: они засоряют базу и не пригодятся в разговоре. Это правило действует на всё, что ты пишешь в записи: на выбор слов, переводы и примеры.

## Шаги

### 1. Получить транскрипт

Инструменты лежат в MCP-сервере `youtube-connector-mcp` и могут быть **deferred** — сначала загрузи схему через ToolSearch
с запросом "youtube transcript". Нужный инструмент — `youtube_get_transcript`. Не угадывай имена параметров.

Параметры: `video_id` (ID видео, а не ссылка целиком) и `language` (`en`).
ID достань из ссылки: для `youtube.com/watch?v=XXXXXXXXXXX` это значение `v`, для `youtu.be/XXXXXXXXXXX` — последний сегмент пути
(ID состоит из 11 символов, параметры вроде `&t=` или `?si=` в него не входят).

Запомни также **чистую ссылку на видео** вида `https://www.youtube.com/watch?v=XXXXXXXXXXX` (собери её из ID, без `&t=`, `?si=` и прочих хвостов): она понадобится в шаге 5 как `source_url`.

Название видео, которое нужно для имени файла в шаге 2, транскрипт не содержит. Возьми его через `youtube_get_video`
(поле `snippet.title`; этот инструмент в том же MCP-сервере).

Если транскрипт недоступен или не на английском — сообщи пользователю и остановись.

**Если ответ слишком большой.** Для длинного видео (примерно от 30–40 минут) `youtube_get_transcript` может вернуть
ошибку вроде «result (N characters) exceeds maximum allowed tokens. Output has been saved to <путь>»: ответ не помещается
в контекст. Это штатная ситуация, а не сбой: инструмент сохраняет весь ответ целиком во временный файл, путь к которому
указан в самом сообщении об ошибке. Не вызывай инструмент повторно и не пытайся читать этот файл в контекст целиком
(он снова не поместится). Файл — это JSON в одну строку, поэтому Read с offset/limit его по частям не прочитает;
работай с ним через `jq` в Bash. Структура ответа:
`{data: {videoId, language, text, segments, segmentCount, availableTracks}, error, pagination}`.

1. Достань только полный текст: `jq -r '.data.text' <путь из сообщения об ошибке> > <файл из шага 2>`.
   Поле `data.segments` не используй: оно дублирует тот же текст кусками с таймкодами и сильно раздувает вывод.
   Сам текст в контекст не выводи.
2. Проверь результат до продолжения: язык — `jq '.data.language, .data.segmentCount' <путь>` (должно быть `en`),
   число слов — `wc -w`, а начало и конец файла (`head -c 300`, `tail -c 300`) должны быть началом и концом видео,
   а не обрезкой. Если конец похож на обрыв посреди фразы, текст неполный: не обрабатывай его как всё видео,
   а получи недостающее или сообщи пользователю, какая часть не вошла.
3. Дальше действуй по шагу 2 (при необходимости раздели файл на части).

То же правило — не терять текст — действует, когда ответ пришёл обрезанным без файла или когда инструмент сам
сохранил транскрипт отдельно: используй сохранённый файл, а не пересказывай по памяти.

### 2. Сохранить транскрипт в файл

Сохрани текст транскрипта в папку:
`/Users/vadimbesten/PycharmProjects/LangHelper/data/transcribation/`

**Обычное видео — один файл:** `{название_видео}.txt`

**Длинное видео — несколько файлов.** Если в транскрипте заметно больше 6000 слов (это около 40 минут речи), раздели текст на части
примерно по 6000 слов и сохрани каждую отдельным файлом: `{название_видео}_part_1.txt`, `{название_видео}_part_2.txt` и так далее
(нумерация с 1, суффикс `_part_{n}` добавляется к названию перед расширением). Режь по границам предложений,
а не посреди фразы, чтобы окна контекста в `prepare_words` оставались целыми. Если текст короче, суффикс не нужен:
транскрипт на 4–5 тысяч слов, даже полученный через временный файл, идёт одним файлом.
Части нужны, чтобы список кандидатов от `prepare_words` оставался обозримым и ничего не терялось.

Имя файла — название видео, очищенное от символов `/ \ : * ? " < > |`.
Если файл уже существует — перезаписывай без вопросов (повторный прогон того же видео).

Формат файла — просто текст транскрипта одной строкой. Заголовок и ссылку не добавлять —
`prepare_words` их не ожидает и просто отфильтрует, но лучше не засорять.

### 3. Вызвать prepare_words

Инструмент из MCP-сервера `langhelper` (при необходимости сначала загрузи его схему через ToolSearch).

```
prepare_words(path="<полный путь к файлу из шага 2>", lang="en")
```

Инструмент вернёт список в формате:
```
Кандидатов: N (уже имеется из этих слов в БД: M)
---
лемма | окно контекста из транскрипта
```

**Если файлов несколько,** шаги 3–5 выполняй для каждой части по очереди, начиная с `_part_1`, и закончи
одну часть полностью (слова добавлены в базу), прежде чем браться за следующую. Тогда `prepare_words` для
следующей части уже видит слова, добавленные из предыдущих, и не предлагает дубли.

### 4. Отобрать слова и составить записи

За **один проход** по списку кандидатов составь записи только для слов, которые стоит учить.

**Пропускай:**
- Имена людей, названия компаний, брендов, продуктов, моделей ИИ (Claude, ChatGPT, Netflix, Palantir…)
- Аббревиатуры (AI, HVAC, CEO…)
- Артефакты лемматизации — слова, которые явно не соответствуют окну контекста.
  **Важно:** spaCy иногда даёт неверную лемму (например, `scar` вместо `scare`, `datum` вместо `data`).
  Сверяй лемму с окном — если она не совпадает с реальным словом в тексте, возьми правильное слово
  из окна и приведи его к базовой форме самостоятельно.
- Слова ниже B1 (базовая лексика: zero, plus, quick, option, fail и подобные, которые любой знает)
- Слова, у которых нет полезного перевода (служебные, числительные, etc.)
- Слишком редкие, узкоспециальные или книжные слова, которые в обычном разговоре почти не встречаются

**Для каждого подходящего слова составь:**

- `lemma` — базовая форма слова (инфинитив для глаголов, единственное число для существительных).
  Если лемма от spaCy неверная — исправь.
- `translation` — один или два **разных по смыслу** ходовых значения через `;` (например: `гвоздь; ноготь`).
  Пользователь учит слово, а не только эпизод из видео, поэтому перевод не должен смотреть на слово лишь под тем
  углом, под которым оно встретилось в видео. Как составлять:
  1. **Первым ставь значение из видео.**
  2. **Потом спроси себя: какие самые частые значения у этого слова в обычной речи?** Если среди них есть значение,
     которого в видео не было, добавь его вторым. Пример: `nail` в видео значит «гвоздь», но в разговоре это слово
     чаще всего про «ноготь», поэтому перевод — `гвоздь; ноготь`.
  3. **Два варианта — это два разных смысла, а не две формы одного.** Пары вроде `прибивать; гвоздь` (глагол и
     существительное одного и того же смысла «гвоздь/забивать») не годятся: второй вариант ничего нового не даёт.
     Второе значение должно быть другим по смыслу (`ноготь`, а не очередной вариант «гвоздя»).
  4. **Второе значение берётся только если оно реально частое** (уровень B1–B2, то, что носитель назовёт сразу).
     Если у слова по сути одно ходовое значение, достаточно одного перевода. Редкие, узкие, специальные или книжные
     значения (C1+) не нужны, даже если они есть в словаре.
  5. Если слово в видео встретилось в редком значении, а частое значение другое, всё равно ставь первым значение из
     видео, а частое значение добавь вторым.
- `examples` — ровно два примера, у которых разные источники:
  - **Пример 1 — только из транскрипта.** Бери окно контекста, вырежи одно законченное предложение с этим словом,
    расставь заглавную букву и знаки препинания, исправь очевидные ошибки распознавания.
    Держись исходных слов, ничего от себя не добавляй. Если предложение получилось длинным и сложным,
    сократи его до самой фразы с этим словом, не меняя исходных слов.
    Если окно настолько испорчено, что из него невозможно вырезать связное предложение, тогда придумай
    этот пример сам (это редкое исключение).
  - **Пример 2 — всегда придумываешь сам, не из транскрипта.** Это обязательное условие: пользователю
    нужен второй, независимый пример, чтобы видеть слово в новом контексте, а не ещё одну цитату из того же видео.
    Даже если в транскрипте несколько подходящих предложений, второй пример бери не оттуда. Он должен
    отличаться по ситуации от примера 1 и быть простым и разговорным: короткое предложение из обычной жизни,
    без сложной грамматики и редкой лексики вокруг (уровень B1 — чтобы незнакомым было только само слово).
    **Если в `translation` два разных значения, пример 2 покажи на втором значении** (тем, которого нет в примере 1),
    например «She bites her nails when she is nervous.» для `nail`. Так обе стороны слова запоминаются.
    Если значение одно, пример 2 покажи в том же основном значении.
  - К каждому примеру — естественный разговорный перевод на русский.

### 5. Добавить слова через add_words

Инструмент из MCP-сервера `langhelper`. Записи передаются списком в параметре `entries`
(`lang` по умолчанию `en`). Вместе с записями передавай **`source_url`** — чистую ссылку на видео из шага 1
(`https://www.youtube.com/watch?v=XXXXXXXXXXX`, без `&t=` и `?si=`). Это параметр самого вызова, один на весь вызов,
а не поле внутри записей. Если видео делилось на части, `source_url` во всех частях один и тот же. Если схема инструмента
не показывает параметра `source_url`, перезагрузи её через ToolSearch и не угадывай: если его там всё равно нет,
сообщи об этом пользователю, а не пропускай молча.

**Порции маленькие: по 15–20 записей за вызов.** Длинный вызов чаще обрывается, и тогда JSON получается битым
и не записывается ничего. Чтобы JSON был валидным:

- Не используй двойные кавычки внутри текста примеров и переводов: в русском тексте ставь «ёлочки», в английском
  перефразируй или используй одинарные кавычки. Обратных слэшей и переносов строк внутри значений тоже не должно быть.
- Каждая запись целиком (`lemma`, `translation`, оба примера) должна войти в порцию; не обрывай порцию посреди записи.
- После каждого вызова проверяй ответ: он должен подтвердить успех, а число добавленных записей должно совпасть
  с числом отправленных.
- Если вызов упал из-за невалидного JSON, считай, что ничего не записано. Не повторяй тот же вызов: раздели порцию
  пополам и отправь заново двумя меньшими вызовами (с тем же `source_url`). Ничего не должно задвоиться: если сомневаешься,
  записалась ли порция, сверься с ответом инструмента или с повторным `prepare_words`.

Пример вызова:

```json
{
  "source_url": "https://www.youtube.com/watch?v=dQw4w9WgXcQ",
  "lang": "en",
  "entries": [
    {
      "lemma": "nail",
      "translation": "гвоздь; ноготь",
      "examples": [
        {
          "sentence": "He hit the nail with a hammer.",
          "translation": "Он ударил молотком по гвоздю."
        },
        {
          "sentence": "She bites her nails when she is nervous.",
          "translation": "Она грызёт ногти, когда нервничает."
        }
      ]
    },
    {
      "lemma": "mitigate",
      "translation": "смягчать; уменьшать",
      "examples": [
        {
          "sentence": "We tried to mitigate the impact of the decision.",
          "translation": "Мы пытались смягчить последствия этого решения."
        },
        {
          "sentence": "Governments act to mitigate the effects of climate change.",
          "translation": "Правительства принимают меры, чтобы смягчить последствия изменения климата."
        }
      ]
    }
  ]
}
```

### 6. Сообщить итог

Коротко: сколько слов добавлено, сколько пропущено как дубли.
Таблицу слов не выводить — она уже в базе.

Если видео делилось на части, дай **одну общую сводку** по всему видео (суммы по всем частям)
и добавь, на сколько частей оно было разбито.

**Об ошибках и обходных путях говори прямо.** Если по ходу работы была ошибка и пришлось её обходить
(например, ответ с транскриптом не поместился в контекст и текст достали из временного файла, или порция в `add_words`
не прошла из-за битого JSON и была отправлена заново), добавь в итог одну строку на каждую такую ошибку: что
произошло и чем закончилось (для транскрипта — сколько слов, язык, начало и конец на месте; для `add_words` — что
ничего не записалось при неудаче и что порция потом добавлена успешно). Даже если всё обошлось, пользователь
должен узнать об этом из итога, а не случайно из логов.

Пример: «Добавлено 47 слов из видео "AI Will Take My Job" (https://www.youtube.com/watch?v=dQw4w9WgXcQ). Пропущено как дубли: 3.»
Пример для длинного видео: «Добавлено 112 слов из видео "AI Will Take My Job" (4 части, https://www.youtube.com/watch?v=dQw4w9WgXcQ). Пропущено как дубли: 9.»
Пример с обходом: «Добавлено 61 слово из видео "eBay Reseller Tips" (https://www.youtube.com/watch?v=dQw4w9WgXcQ). Пропущено как дубли: 5. Транскрипт не влез в один ответ, я достал его из временного файла и проверил: 4634 слова, язык en, начало и конец на месте. Одна порция add_words не прошла из-за битого JSON, ничего не записалось; отправил её заново двумя меньшими вызовами, всё добавлено.»
